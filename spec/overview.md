# Overview

## Goals

- Edit ZMK `.keymap` files visually: layers (bindings, names, sensor/encoder bindings), combos, with every built-in behavior plus the behaviors and macros the keymap defines itself.
- Work on **git repositories** rather than through a hosted GitHub App: any number of zmk-config repositories, cloned by the app (SSH or HTTPS) or used in place from an existing checkout.
- Full git round trip from the UI: status, diff, commit, push, pull (fast-forward or rebase), fetch, branch switch/create, discard.
- **GitHub integration** for firmware: list GitHub Actions runs of the current branch, download an artifact, save individual files, flash a `.uf2` to a mounted bootloader drive, trigger a workflow run.
- Keep the original editor's core look: left layer list, the physical layout with rotated keys, behavior tag in the key corner and the main legend centered, sensor knobs under the keyboard. Modernize the rest (dark-first theme, searchable pickers, hold/tap legends, colour swatches, undo/redo).
- Ship as one executable with the UI embedded; data in one SQLite file.

## Non-goals

- Compiling firmware locally (GitHub Actions does that).
- Expanding C preprocessor macros. Keymaps whose layers are generated by macros (zmk-helpers `ZMK_LAYER(...)` etc.) are detected and shown as not editable; nothing in them is rewritten.
- Multi-user use, authentication, remote access. The server binds to loopback.
- Editing behavior/macro definitions (they are listed read-only with their source).

## Stack

- Go 1.27, stdlib `net/http`, `modernc.org/sqlite`, `golang-migrate`. Git via the `git` CLI.
- React 19, TypeScript, Vite, Tailwind v4, shadcn/ui (radix), hugeicons, TanStack Query, react-router, cmdk, sonner.
- Built-in keycode catalogue from the ZMK docs (MIT, `internal/zmkdata/LICENSE`).
